# Conversation execution and incident recovery

The answering agent gives a short plan, explains material discoveries as work
continues, performs already authorized corrections, verifies the outcome and
reports any remaining conflicts. The owner should not have to inspect raw tool
results, repeat remembered information or chase a suspended command.

## Evidence continuity

The shared memory budget retains exact lookup results for the coordination
round. Those results are persisted with the run and supplied to peer and return
turns as attributed evidence. Spending the single lookup allowance does not hide
the capability or discard its results. Repeated calls return retained evidence
without another database search. Record versions and source spans remain intact;
they grant no extra write authority. Source records and native documents remain
unchanged by these serving fixes.

Person retrieval prefers a substantive native dossier over an empty entity index.
Full-name queries prioritize specific name matches over relatives sharing a
surname. Ultron receives an automatic, local list of saved courses by term before
the first model call, within its existing course-reader permission. This is not
proof of enrollment in unlisted courses and does not replace Google Calendar.

## Host command recovery and progress

Deploy the current host broker with both `broker.sock` and `events.sock` exposed
through the existing private directory mount. The completion stream resumes the
original saved provider boundary. Host recovery starts only when that directory
mount is configured; an isolated database rehearsal must not create room progress
events while checking schema preservation. If the stream is unavailable, the backend
reconciles saved operation receipts, at most every ten seconds, without running
commands again or polling a model. A pending command gets one explanatory delay
notice after thirty seconds. A completed result held by policy or spending limits
is explicitly surfaced instead of silently remaining pending.

Critical watchdog findings are projected from completed System Ops results
immediately, before another model turn. A later pending command retains the
finding and its owner-local observation time alongside its running status.
Private consultations do not publish these observations into the public room.

Desktop and Android retain and render progress even after streaming pauses or
when an agent has already written prose. Meaningful statuses take precedence over
generic tool labels. Event replay does not duplicate their text.

## Watchdog delivery and bounded protection

The factual security warning is dispatched independently of model assessment and
automatic host response. Configured owner devices receive a separate,
deduplicated push alongside Telegram. A later assessment updates the confirmed
Telegram message only while the original owner route remains unchanged.

Connect, connect-timeout and pool-timeout failures mean no HTTP request was sent;
the watchdog retries those after sixty seconds. Read/write failures and uncertain
acknowledgements remain held for reconciliation and are never blindly resent.
The Incident Journal retains the actual send state and assessment.

High ingress and flood incidents invoke the broker's fixed `security_response`
operation. It accepts no model-selected command. The root-owned
`/opt/speda-operations/orion-host-ops/security-policy.json` must explicitly list
`unused_udp_ports`. Without that policy, no automatic rule change is allowed.
The responder checks for listeners, confirms UFW is active, backs up its user
rules, inserts the narrow UDP deny when necessary and verifies it. It respects
the deployment lock and maintenance inhibit. It does not enable a disabled
firewall, change SSH, ban arbitrary IPs or stop services.

Host firewall rules cannot prevent upstream link saturation or establish the
provider's suspension reason. The owner-facing result preserves that unresolved
provider requirement instead of claiming a complete DDoS fix.

Regression evidence covers shared source/version transfer, dossier selection,
automatic academic context, receipt recovery without redispatch, progress replay
and rendering, early warning during slow assessment, and bounded host protection.
