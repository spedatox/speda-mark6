# Proactive Cortex — recall, judgment and ownership

Engineering decision record, 21 November 2026. This revision covers the first model call in personal chat, public specialist exchanges and the accuracy of tool outcomes. The existing coordination, memory and publication services remain the implementation points. The owner’s debug exports are private. The cases below use synthetic wording.

## Diagnosis

A user who says “the time changed” expects the assistant to identify the current plan before asking which time. A user who says “phew” after an exam gives almost no lexical evidence. A specialist who finishes a task expects the lead to draw the conclusion. Each failure can look like weak model reasoning even when the model never received the relevant turn or the lead never received a chance to speak.

Three production exports contained 30 admitted runs including retries. In the travel-planning chat 11 of 16 prepared reads reached their deadline. The coding chat recorded 6 of 7 and the later travel chat 5 of 7. All 23 runs in the two travel chats recorded zero automatic recent references. A read-only archive replay previously measured 97–332 ms for individual lookups against a 150 ms recent-history allowance. The vector index alone cannot explain this failure. A separate failure survived a generous deadline when a greeting retrieved stale reports containing the assistant’s name.

The coding trace also contains two distinct operational failures. An invalid inventory path left an admitted read unresolved. Separately, an actual process timeout left cleanup unverified. The first has a known outcome and should be recorded immediately. Retrying the second can duplicate work. A local change, completed worker turn or successful wrapper exit supplies insufficient evidence of a remote Git update.

## Runtime behavior in this revision

1. **First-call context.** Run prepared memory and recent conversation retrieval concurrently. Allow up to 800 ms for the prepared read and 500 ms for recent episodes within the existing shared five-second memory allowance. The former 250/150 ms caps discarded usable evidence on the production archive. These are deadlines, not delays imposed on fast reads. Each lane can contribute independently. The normal server startup warms the PostgreSQL search projections.
2. **Episode selection.** Search eligible messages preceding the original input and exclude the current session for automatic continuity. Keep matching source text, original speaker, timestamp and message reference. Prefer an owner turn for an unanchored opening. Preserve an assistant quotation when it carries the match. For an ambiguous reaction two recent plausible threads can be supplied. A simple greeting containing the current persona’s name does not justify surfacing old reports.
3. **Named private conversations.** An explicit reference in the admitted owner message can select a named persona in a one-to-one chat. English and Turkish forms cover common direct references. The receiving room must be personal, and the source must be a single-persona room of the same owner with no membership changes. Project chats, automation, worker prompts, quoted attachments and a weekday by itself cannot grant cross-persona access. Hidden and retired sources, private consults and future turns are filtered. Excerpts are appended only to the receiving step’s live prompt. Resumption checks the references against the current audience. Unsupported paraphrases can miss this lane.
4. **Lead ownership.** In one transaction admit the specialist contribution and reserve a caller return, subject to the contribution limit. Several questions from one contribution share one return. Release it after nested replies settle. A specialist answering its already-waiting caller can use its current contribution. A reverse address or direct mention should not produce another independent exchange. The lead sees the answer and decides what follows.
5. **Operational truth.** A known path or binary-viewer denial completes the read receipt. The inventory remains available in the same workspace. A sandbox hold identifies the prior receipt. Rejected, unavailable and unsuccessful command outcomes remain visible to the run. An actual unknown process outcome stays held. Existing release and Git services retain responsibility for verifying the accepted revision and remote identity.
6. **Withdrawal.** A fresh, standalone owner withdrawal receives a short acknowledgement before model or tool execution. Compound requests and quoted phrases stay on the normal judgment path. This boundary covers the newly admitted turn. Stopping work already in flight uses the existing cancellation and reconciliation lifecycle.
7. **Diagnostics.** Record the recent lane’s coverage, time and reference count alongside the prepared result. This distinguishes an exhausted deadline, an ordinary greeting, audience restrictions, no match and prompt packing. Count the source in the actual model input when assessing retrieval quality. Debug metrics alone cannot say that an excerpt was useful.

## How SPEDA should exercise judgment

For a confirmed ticket, identify the journey, date and direction from the source. If a recent owner conversation supplies the purpose of the trip, connect it. If the return leg is unbooked, preserve that uncertainty. Where permission and the question warrant a calendar read, look for affected commitments first. “You’re heading home Saturday. You have a Monday appointment here. How long are you planning to stay?” is useful only when those three facts are supported. Without the appointment or another planning consequence, a shorter reply may be the better decision.

For a fresh reaction after an exam, the previous personal conversation can make “How did the exam go?” a natural first reply. If there are two recent stressful events, use tentative wording or let the owner lead. An upcoming event does not establish attendance, completion or a result. The runtime supplies evidence for this choice. It contains no exam-to-reply or ticket-to-calendar rule.

For coding, bind work to the selected project and record the artifact revision. An inventory denial means the read did not happen. A lost execution receipt means the effect is unknown. A local commit is evidence of a local revision. A publication claim requires a remote ref matching the intended revision at the authorized destination. A specialist may finish a diagnostic report successfully while the overall publication remains blocked.

## Verification and remaining design work

The read-only production comparison uses the 30 original admissions, saved step history, owner-local time and original input cutoffs against the current database. It does not recreate the historical database snapshot. Current room membership, hidden messages and retired sources continue to apply. The replay creates no chat, calls no model and writes no personal records. A cold-process experiment that skipped startup warmup produced frequent timeouts; timing conclusions must use the normal startup path and report cold behavior separately.

The warmed candidate completed all 29 requested prepared reads without a deadline. One standalone withdrawal skipped retrieval. It supplied recent excerpts in 24 of 30 turns. The final named-peer replay withheld private excerpts because the receiving room currently contains a second persona. The earlier planning episode was present for both the implicit changed-time message and the explicit destination follow-up. Median wall times per chat were 289, 150 and 203 ms for the combined preparation path, including skipped retrieval in the last sample. These small samples measure availability and latency. They do not estimate an answer-quality pass rate.

Test the system at four boundaries:

| Boundary | Positive case | Negative control or failure |
| --- | --- | --- |
| Retrieval | Recent owner exam statement in the first prompt, specialist quote paired with its owner turn, named personal exchange | Greeting, another owner, group room, weekday, hidden original on resume |
| Judgment | Link a ticket to a verified active commitment, or react naturally to a timely exam cue | Conflicting trips, uncertain endpoint, ambiguous sigh, itinerary update that needs no interruption |
| Coordination | Absent specialist invited, answers lead, one synthesis delivered | No capacity for a return, duplicate address, queued newer owner input |
| Execution | Failed inventory read followed by a valid listing, confirmed command outcome | Unknown cleanup, rejected publication, empty checkout, external lookup unavailable, standalone withdrawal |

Deterministic tests can verify the first prompt, turn graph, receipts and lack of unwanted effects. They cannot establish conversational taste. For a behavioral release assessment, hold out paraphrases in both languages, include distractor dates and multiple plausible episodes, run the production model several times, and have a reviewer mark the source, inferred intent, next action and interruption cost. Track first-call relevant-episode recall, irrelevant-episode injection, correction uptake, useful initiative, unnecessary questions and verified completion separately. Compare on matched cases and report denominators.

**Further work.** A durable link from an older open obligation to the later owner turn that replaces it would allow suppression of stale reports across runs. Store the owner, room, original obligation, replacing input and reason. A newer message alone is insufficient because two tasks may be independent. Check the link at delivery and keep both receipts for inspection. For semantic episode retrieval beyond the recent window, compare a derived session index with the existing fallback on blind cases before changing storage. For publishing, grade a disposable repository run through the real authorized publisher, including rejected credentials and remote ref verification. These are separate acceptance gates from faster retrieval or a resolved file-read denial.
