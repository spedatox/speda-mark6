# SEO — making "SPEDA Mark VI" resolve to this project

Before this pass, searching **SPEDA Mark VI** returned patrol boats, Lincoln
Continentals and Halo armour. The repository was public but carried *no
description, no topics, no homepage and no website* — so there was nothing for a
search engine to index beyond a README it had never been pointed at.

The good news is that this is the easiest class of SEO problem there is.
"SPEDA" is a coined token with no serious competitor. Nobody has to be
outranked; the entity simply has to **exist** in a form crawlers can find, parse
and trust. That is what the work below builds.

---

## The strategy in one paragraph

Own the whole first page rather than one link on it. There are already **nine
properties** under this account that legitimately concern SPEDA — `speda-mark6`,
its five predecessor generations, `speda-go`, `forge-mark1`, and the new Pages
site with its five sub-pages. Each one that carries the brand token, describes
itself accurately, and links to the canonical entity is another result Google
can return and another vote that "SPEDA" means *this*. A single repo is one
result; a connected cluster is a first page.

**Corrections that came out of writing the pages from the code.** Every page was
written against `app/profiles/*.py` and `app/prompts/agents/*/01_identity.md`
rather than paraphrased from the README, which surfaced four drifts:

- **Ultron is an academic-life specialist**, not a research agent. Its declared
  domain is "academic life & university/work balance — study, planning,
  coursework"; research is explicitly a tool in service of that, not the identity.
- **Optimus is no longer the only externally-backed agent.** `centurion.py` also
  declares `external_backend = True` and can be served by its own peer with its
  own Cell. `CLAUDE.md` still calls Optimus "the single exception".
- **Agents are not separated by tool access.** Every profile now declares
  `tool_allowlist = None`. What differs is identity, memory scope and a few
  architectural privileges — so the site says that instead of repeating the
  usual "each agent has its own tools" line.
- **The roster emoji were wrong** for Optimus (green, actually `#2f4f8f` deep
  blue) and Orion (purple, actually `#e0703a` orange). Both corrected in the
  README; the site uses the client accents throughout.

Separately, the backend `DocTheme` accents for Optimus and Orion disagree with
all four client brand tables — flagged as its own task, not fixed here.

## What only you can do

These five need your GitHub login. Nothing below is reversible-with-difficulty;
every one can be undone from a settings page.

### 1. Turn on Pages — *do this first, nothing else works without it*

**Settings → Pages → Build and deployment → Source: GitHub Actions.**

Until this is set, `pages.yml` fails with "Pages site not configured". Once set,
push `main` and the site appears at `https://spedatox.github.io/speda-mark6/`
within a couple of minutes.

### 2. Set the repository metadata

This is the single highest-leverage item on the list. Google builds a repo page's
title tag out of the description field:

```
GitHub - spedatox/speda-mark6: {description}
```

An empty description means an empty snippet and nothing to match a query against.

```bash
export GITHUB_TOKEN=ghp_your_token_here
./scripts/seo/apply-repo-metadata.sh --apply --siblings
```

Run it without `--apply` first — it prints exactly what it would write and
touches nothing. The `--siblings` flag also updates `speda-go`, `forge-mark1`
and the five predecessor repos, which is what converts a lone repo into a
cluster. Prefer clicking? The same values are in the script's header; paste them
into each repo's **About** panel by hand.

### 3. Upload the social preview to GitHub

**Settings → General → Social preview → Upload an image**, and give it
`site/assets/og.png`. This is what renders when the repo is linked anywhere, and
GitHub's default (a grey box with the repo name) converts far worse.

### 4. Register with the search engines

- **Google Search Console** — <https://search.google.com/search-console>. Add a
  **URL prefix** property for `https://spedatox.github.io/speda-mark6/`. Verify
  by downloading the HTML verification file, dropping it into `site/`, and
  pushing. Then **Sitemaps → submit** `sitemap.xml`, and use **URL Inspection →
  Request indexing** on the homepage.
- **Bing Webmaster Tools** — <https://www.bing.com/webmasters>. Worth the ten
  minutes on its own terms, and Bing's index is what several AI answer engines
  read from. It can import your Search Console property directly.

### 5. Spend the links you already own

- **Your GitHub profile README** (a repo named `spedatox`) is the highest-traffic
  page you control on GitHub. A line at the top pointing to SPEDA Mark VI passes
  the most internal weight of any single link available to you.
- **Your X profile** (`@spedatox`) — put the site in the website field and pin
  one post about it. The `twitter:` card tags are already in place, so the link
  unfurls with the card above.
- **Predecessor READMEs** — a note at the top of each older generation. Exact
  copy, ready to paste:

  ```markdown
  > **Superseded by [SPEDA Mark VI](https://github.com/spedatox/speda-mark6)** —
  > the current generation of S.P.E.D.A., the Specialized Personal Executive
  > Digital Assistant. Read the overview at
  > [spedatox.github.io/speda-mark6](https://spedatox.github.io/speda-mark6/).
  ```

## What to honestly expect

**"Instantly" is not a thing anyone can sell you.** Indexing is Google's
decision and its schedule, not ours. What the shape of this particular problem
tells us:

- **Days, not months, to appear.** With Search Console verified and indexing
  requested, a `github.io` page on an established host typically lands in the
  index within a few days to two weeks.
- **Ranking should be immediate once indexed.** The exact phrase "SPEDA Mark VI"
  has *no* competing document. There is nothing to displace. The reason it
  returns patrol boats today is that Google matches "Mark VI" and ignores
  "SPEDA" as noise — the fix is having any authoritative page that uses both
  tokens together, repeatedly and in structured form. That now exists.
- **The cluster is what produces "everywhere".** One indexed page gives you one
  result. Nine properties that agree with each other give you a first page.
- **Zero stars is the real ceiling.** Backlinks and engagement are what turn a
  correct listing into a durable one, and no amount of on-page work substitutes.
  If this ever gets posted somewhere real, that will do more than everything in
  this document combined.

Two things deliberately *not* claimed: `FAQPage` structured data rarely produces
visual rich results anymore (Google restricted them to authoritative health and
government sites), but it remains excellent input for AI answer engines, which
is why the FAQ page exists. And `site/robots.txt` is advisory rather than
authoritative — see below.

## Constraints worth knowing before you change things

**`robots.txt` only counts at the host root.** For a project page the effective
file is `https://spedatox.github.io/robots.txt`, which is owned by a repository
literally named `spedatox.github.io`. Our copy becomes authoritative the moment a
custom domain is attached. This is why the sitemap must be submitted directly in
Search Console rather than left to discovery.

**A custom domain would be strictly stronger**, and the production domain is
deliberately kept out of this public repo (it lives in `$DOMAIN`, injected by
`deploy.sh`). If you ever want the site on a real domain: add `site/CNAME` with
the bare hostname, point a DNS `CNAME` at `spedatox.github.io`, then update every
absolute URL — canonical, `og:url`, `og:image`, `sitemap.xml`, `robots.txt`,
`llms.txt` — and re-run the metadata script to fix the homepage field.

**Keep the metadata honest when the product changes.** The site states specific
facts: eight agents, seven providers, the agent accents. If the roster or the
provider list changes, the site, `llms.txt` and the repo description all need the
same edit — a confidently wrong entity description is worse for an answer engine
than a vague one. Bump `lastmod` in `sitemap.xml` when you make a substantive
edit; leave it alone for typo fixes.

## Verifying the result

```bash
# Serve the site exactly as Pages will
.venv/Scripts/python.exe -m http.server 4820 --directory site
```

Then, once it is live:

- **Rich Results Test** — <https://search.google.com/test/rich-results> against
  the live URL, to confirm the structured data parses on Google's side.
- **Card validators** — paste the URL into X, Slack or Discord and check that
  `og.png` renders.
- **`site:` query** — `site:spedatox.github.io/speda-mark6` shows exactly what is
  indexed so far. Empty means not yet crawled, not broken.
- **The real test** — search `SPEDA Mark VI` and see what comes back.
