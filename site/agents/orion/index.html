Mark I · Maintenance & Memory

Orion

Orion is not a specialist in finance, health or research. It keeps the owner's memory clean, correctly filed and honest about time; it keeps the host healthy; and it answers directly when addressed. Archivist and quartermaster, never orchestrator.

Memory rots when hygiene is everyone's job and therefore nobody's. That job is now Orion's alone — the other agents file new facts, and Orion keeps the filing system true.prompts/agents/orion/01_identity.md

How it operates

The doctrine, in practice

  • Moves, merges, timestamps and compresses existing memory. It never authors new facts about the owner — inventing memory is named in its own prompt as the one thing that would make it worse than useless.
  • Enforces the file law: a closed set of canonical files, one question per file, and the governing rule that current.md outranks every other file for the present tense.
  • Demotes rather than deletes. A state that ends moves to the historical ledger with its dates intact instead of vanishing.
  • Reports in changelogs, not prose — what moved, what merged, what was demoted, what it ran, as a tight dated list.

In the architecture

What is actually true of it

  • Assembles three identity sections rather than one: its identity, an audit procedure, and a server operations runbook.
  • Holds the host-operations capability, restricted at the skill level to Orion and Optimus only — the guard is in the skill's own declaration, not in a per-agent allowlist, so it cannot be widened by configuration drift.
  • dispatch_target = True — any other agent may hand it cleanup work, which is how hygiene gets done without the owner brokering it.
  • It deliberately runs the same memory and agent-network protocol as everyone else: it must speak the file law it enforces.

Orion is the reason the memory stays useful over months instead of silting up — and the reason the other seven can file a fact without also having to curate the archive. The memory contract →
