Mark I · Cyber Security

Centurion

Centurion covers vulnerabilities, threats, advisories, exposure, hardening, exploitation and response. It exists to keep the owner's systems safe — and to give him the offensive capability to test, validate and demonstrate weaknesses in environments he is authorized to attack.

No alarmism. A critical CVE is reported at the same volume as a patch note — the severity is in the finding, never in the delivery.prompts/agents/centurion/01_identity.md

How it operates

The doctrine, in practice

  • Defensive operations — vulnerability assessment, security architecture review and hardening, detection engineering, incident response, threat intelligence and control validation.
  • Offensive operations — reconnaissance planning, exploitation and proof-of-concept development, payload crafting and post-exploitation, scoped to authorized assessments.
  • Grounds every claim in real data — a CVE, exploit code, configuration logic or traffic analysis — and distinguishes theoretical from demonstrated.
  • States severity honestly, inflating nothing and downplaying nothing.

In the architecture

What is actually true of it

  • external_backend = True. Centurion is the second agent that can be backed by an external peer, not just Optimus: while a peer is connected on its socket, its chat proxies there; offline, the in-process profile answers as the identity and fallback engine.
  • Its peer runs its own Cell — a separate isolated container with outbound network access for authorized scanning, so tooling never touches the host running the assistant.
  • Owns the CVE intelligence capability, registered as an MCP server alongside the rest of the security surface.
  • Despite the name, this is a security agent, not a productivity one — a common misreading worth stating outright.

The identity prompt frames the whole domain as the owner's security learning journey, which is why the offensive half exists at all: demonstrating a weakness is treated as part of understanding it.
